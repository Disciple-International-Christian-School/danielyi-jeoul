# 다니엘의 저울 — 프로젝트 사례 연구

**Language / 언어:** [English](PROJECT_CASE_STUDY.md) | [한국어](PROJECT_CASE_STUDY.ko.md)

## 문제와 목적

DICS에는 종이 벌점표를 실제 생활지도 업무로 연결할 도구가 필요했다. 상·벌점 기록, 반성문 제출 확인, 반별 공지, 주간·정산기간별 후속 조치를 지원하는 관리자 전용 시스템이 다니엘의 저울이다. 학생은 이 앱에 로그인하지 않는다.

여러 학교 앱이 같은 학생을 서로 다른 방식으로 식별하면서 문제가 확대됐다. 다니엘의 저울은 정수형 학생 ID를, Study Planner는 인증 UUID를 사용했다. 기록을 안전하게 연결하려면 공통 학생 식별체계가 먼저 필요했다.

## 설계 판단과 비용

| 결정 | 이유 | 비용·한계 |
| --- | --- | --- |
| `core.students.id`와 로그인 신원 분리 | 계정 없는 학생도 존재하며 인증 변경이 학생 신원을 바꾸면 안 됨 | 명시적 연결표와 검증된 이관 필요 |

| 개인 관리자 계정과 인증된 감사 주체 | 직접 입력한 이름 대신 실제 작업자 추적 | 개인계정의 실제 보급이 완료되어야 함 |

## 기여와 도구 사용의 구분

기록에는 Lovable·Replit·Cursor·Claude Code·GPT 지원 작업과 사람의 운영 판단이 함께 등장한다. AI를 활용한 개발 프로젝트로 설명하고, 저장소 전체 작업을 한 학생의 단독 성과로 표현하지 않는다.

EC 제출 시 지원자가 직접 담당한 요구사항·판단·구현·검증을 커밋 또는 PR과 연결한다. 저장소만으로 개인의 저작·주도성이 입증되지는 않는다. 배포 상태와 운영 책임은 학교 담당자의 확인을 거쳐 기술한다.

## 남은 과제와 한계

전교생 학번 정책, Study Planner 이관 완료 여부, 개인 관리자 계정 보급, 기존 호환 경로 제거는 현재 Owner 확인이 필요하다. 사진 입력 보조와 통합 학생 프로필은 인용 기록상 계획 단계다. 시간 절감률·도입률·학습성과 향상·독립 보안 인증은 주장하지 않는다.

제출 자료에는 가상 예시와 집계 근거만 사용한다. 과거 계정 안내에 학생 식별정보와 PIN이 있어 영·한 빈 양식으로 대체했다. 대체 작업이 과거 Git 객체 삭제나 비밀번호 교체를 의미하지 않는다. 저장소 접근을 공유하기 전 Owner가 과거 노출과 인증정보 유효성을 확인해야 한다.

후속 주간 원장·수기 시험·규칙 변경은 [현재 규칙](DISCIPLINE_RULES.ko.md)과 [이력 전환](HISTORY_AND_BACKFILL.ko.md)을 참조한다. 앞선 수치는 당시 관측이며 현재 잔고·대상 수가 아니다.
