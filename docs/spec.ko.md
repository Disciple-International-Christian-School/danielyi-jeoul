# 다니엘의 저울 — 원본 35개 절 요구사항

**Language / 언어:** [English](spec.md) | [한국어](spec.ko.md)

> 초기 개발 요청을 한국어로 정리한 역사 자료다. 현재 구현을 그대로 설명하지 않는다. 직접 입력 작성자, 달력 월 벌점, 학생 CRUD, 초기 기술 스택은 이후 Core·인증 감사·NET·정산 설계로 변경되었다. 현재 상태는 변경 이력과 전환 실행서를 우선한다. 이 문서는 실제 기능을 갖춘 앱을 요구했으며 목업만을 요구한 것이 아니다. 사용자 화면의 언어는 한국어다.

## 1. 개요

학생 기본정보·상점·벌점·항목·반성문·처분과 주간/월간 자동 상태를 관리하는 내부 관리자 시스템. SEONDO(선도부)와 SASAENG(사생회) 두 역할만 있고 학생은 로그인하지 않는다.

## 2. 권장 기술

당시 권장안은 Next.js App Router, TypeScript, React, Tailwind, shadcn/ui, PostgreSQL, Prisma, 안전한 인증·서버 권한·Zod 검증이었다. 관리형 DB/Auth인 Supabase도 허용한다. 클라우드 배포 가능하고 중요한 데이터는 실제 DB에 영속화한다. 하드코딩 가상 프론트엔드만 만들지 않는다. 실제 선택은 이후 Vite/Supabase 구조다.

## 3. 인증

관리자는 ID/이메일·비밀번호로 로그인하고 대시보드로 이동한다. 세션에 역할을 보관하고 서버에서 권한을 검사한다. 서로의 제한 기능을 수정하지 못하며 버튼 숨김만으로 통제하지 않는다.

## 4. 학생 데이터

id·name·grade·createdAt·updatedAt만 기본 저장한다. 전화·주소·주민번호·학부모·의료·불필요한 민감정보를 저장하지 않는다. 현재 상/벌점·주간/월간 벌점·현재 처분·반성문·자동 상태는 기록에서 계산한다.

## 5. 학생 관리

이름 검색·학년 필터·정렬·상세·추가·수정·삭제. 기본 정렬은 현재 벌점 내림차순 → 학년 → 가나다순. 표에는 학년·이름·상점·벌점·처분·상태·상세 링크를 표시한다. 이 초기 CRUD 요구는 이후 Core 원본 관리로 대체된다.

## 6. 점수 기록

id·studentId·type(POSITIVE/NEGATIVE)·item·points·date·enteredByName·createdAt·updatedAt. 원본 요청은 enteredByName을 관리자가 직접 입력하고 로그인 이름을 자동 대입하지 않도록 요구했다. 이후 인증된 작성자 추적으로 개선됐다.

## 7. 벌점 입력

학생·항목·점수·기입자·반성문 제출 여부. 학생은 검색 드롭다운, 항목은 검색 가능한 콤보박스. 기본 항목은 지각·복장불량·신발장 미정리·선생님 재량·기타 직접 입력. 처음 세 항목 점수는 임의로 정하지 않고 관리자 설정으로 둔다. 고정 점수 선택 시 자동 채움/오수정 방지, 기타는 항목·점수 직접 입력.

## 8. 선생님 재량

고정 점수가 아니며 1·2·3·4·5 중 정확히 하나를 선택한다. 서버도 1–5 범위를 강제한다.

## 9. 상점

별도 입력 폼에 학생·상점 항목·점수·기입자·날짜를 둔다. 당시 직접 입력 기입자 규칙이 동일하며 향후 상점 항목 관리도 가능해야 한다.

## 10. 반성문

submitted·submissionDeadline·submittedAt. 당시 규칙은 벌점 당일 마감, 기본 미제출, 관리자가 제출 체크. 다음 날에도 미제출이면 2배 제출 대상 표시. 원본 기록·발생일·마감을 보존한다. 전체/완료/미제출/2배 필터가 있는 전용 화면을 둔다. 이후 시간형 마감 규칙이 이 요구를 보완한다.

## 11. 자동 선도 규칙

주간 벌점 기록 3회 이상 또는 벌점 8점 이상이면 체력훈련 대상. 월간 벌점 20점 이상이면 징계위원회 대상. 상태만 자동 표시하고 실제 처분은 관리자가 확정한다. 자동 처분 생성은 금지한다. 이후 주간 NET·정산기간 규칙으로 변경된다.

## 12. 주간 계산

과거 벌점에서 계산하며 새 주 표시 합계만 0부터 시작한다. 기록과 과거 주간 합계를 지우지 않는다. 연속 주 판정을 위해 조회 가능해야 한다. 학교 시간대 월요일 00:00~일요일 23:59:59, 기본 Asia/Seoul을 사용한다.

## 13. 사생회 처분

운동금지·간식금지·면회금지·귀가 지연·귀가 금지를 지원한다. 시스템이 임의 선택하지 않고 담당자가 결정한다.

## 14. 주간 5점

5점 이상이면 처분 선택 필요를 표시하고 운동·간식·면회금지 중 하나를 수동 선택한다.

## 15. 주간 10점

10점 이상이면 위 세 종류 중 두 개를 선택한다. 두 개 선택 안내와 프론트/서버 유효성 검사를 제공하고 자동 선택하지 않는다.

## 16. 3주 연속

3주 각각 5점 이상이면 귀가금지 조건 충족을 표시한다. 과거 주간 자료에서 계산하며 실제 적용은 명시적 설정이 없는 한 수동 행정 조치다.

## 17. 처분 위반

활성 처분에 id·studentId·punishmentType·startDate·endDate·enteredByName·createdAt·updatedAt을 저장한다. 권한 있는 담당자가 위반을 기록하면 귀가금지를 표시한다. 위반 발생을 자동 추정하지 않는다.

## 18. 처분 등록

학생·이번 주 벌점·종류·시작/종료일·기입자를 모달에 둔다. 당시 기입자는 직접 입력. 5점 이상 하나, 10점 이상 두 개를 허용하고 현재 주간 점수를 표시한다. 취소/등록 버튼은 실제 동작한다.

## 19. 항목 관리

항목 추가·수정·삭제/비활성·고정 점수 변경·사용 여부 관리. itemName·pointValue·isFixed·isActive·createdAt·updatedAt. 선생님 재량은 isFixed=false와 1–5 범위다.

## 20. Excel 가져오기

벌점 항목·벌점 열을 업로드 → 파싱 → 미리보기 → 검증 → 오류 표시 → 확정 → 저장한다. 잘못된 데이터를 즉시 반영하지 않는다. 재량 항목은 고정값이 아닌 1–5 특례로 처리한다.

## 21. 수정·삭제

권한에 따라 학생·점수 기록/항목/점수/기입자·반성문·처분 종류/기간을 수정한다. 삭제는 대상 설명과 확인을 거친다. 이력은 가능하면 논리 삭제하고 계산·감사용 과거 기록을 보존한다.

## 22. 학생 상세

/students/[id]에 이름·학년, 현재 상/벌점·이번 주/달 벌점, 정상/훈련/위원회/반성문/각종 금지 상태를 표시한다. 벌점 이력에는 날짜·항목·점수·기입자·반성문·수정/삭제, 처분 이력에는 종류·기간·기입자·상태를 표시한다.

## 23. 대시보드

전체 학생·주간 대상·미제출·2배·현재 처분 카드와 학년·이름·상/벌점·처분·상태 표. 검색·학년/상태 필터·정렬과 눈에 띄는 벌점 입력 동작을 둔다.

## 24. 메뉴

다니엘의 저울 브랜드와 대시보드·학생·벌점·상점·반성문·처분·항목 관리 메뉴. 선도부에는 생활지도 메뉴, 사생회에는 대시보드·학생·처분을 표시한다. 메뉴 표시는 실제 서버 권한을 대체하지 않는다.

## 25. DB 모델

정규화 관계형 구조와 FK/인덱스. 원본 제안 필드:

```text
User: id, username, passwordHash, role, createdAt, updatedAt
Student: id, name, grade, createdAt, updatedAt, deletedAt
PointItem: id, name, type, fixedPoints, isFixed, isActive, createdAt, updatedAt
PointRecord: id, studentId, pointItemId, type, customItemName, points,
 enteredByName, recordedAt, createdAt, updatedAt, deletedAt
ReflectionRecord: id, pointRecordId, submitted, submissionDeadline, submittedAt
Punishment: id, studentId, type, startDate, endDate, enteredByName,
 violated, violationRecordedAt, createdAt, updatedAt
WeeklySummary: id, studentId, weekStart, weekEnd, penaltyPoints,
 penaltyRecordCount, createdAt, updatedAt
```

이름·학년·학생별 점수·기록일·학생+주차·처분 학생+기간에 인덱스를 둔다. 실제 구현은 인증·뷰 계산·Core 구조로 발전했다.

## 26. 서버 로직

인증, 학생/항목/기록/처분 CRUD, 반성문 상태, 주간/월간 계산, 상태 판정, Excel 입력을 서버에서 검증한다. 클라이언트가 보낸 계산 상태를 믿지 않고 원본 DB에서 도출한다.

## 27. 재사용 UI

사이드바·헤더·버튼·입력·검색·선택·콤보박스·체크·라디오·배지·카드·표·모달·알림·삭제 확인·빈/로딩/오류 상태·페이지 처리를 일관되게 구성한다.

## 28. 반응형

1440px 데스크톱을 우선하고 태블릿·모바일도 지원한다. 모바일 메뉴는 서랍형, 표는 가로 스크롤 또는 카드, 모달은 작은 화면에 맞추고 핵심 동작을 유지한다.

## 29. 메시지

학생·항목·점수·기입자 누락, 재량 1–5 제한, 처분 최대 두 개·미선택 등을 명확한 한국어로 안내한다. 벌점·상점·처분 등록, 학생 수정, 항목 저장 성공도 표시한다.

## 30. 보안

비밀번호 해시·안전한 세션·서버 역할·입력 검증·SQL 주입 방지·해당 시 CSRF·안전한 쿠키·비밀번호/불필요한 개인정보 비노출·파일 검증/크기 제한/값 정제를 적용한다. 프론트 권한에만 의존하지 않는다.

## 31. 감사

주요 작업의 주체·행동·대상·시각을 추적한다. 원본의 직접 입력 기입자와 인증 관리자는 별개였으며 이후 인증 기반 기록으로 개선됐다.

## 32. 개발 seed

두 역할과 가상 학생 네 명(학년 2·1·3·2), 기본 항목을 준비한다. 실제 학생을 seed에 쓰지 않는다. 처음 세 항목 고정 점수는 학교 설정 전까지 임의 지정하지 않는다.

## 33. 규칙 요약

주간 3회 또는 8점=훈련, 월간 20점=위원회, 주간 5/10점=처분 1/2개 수동 선택, 3주 연속 5점=귀가금지 조건, 위반=귀가금지, 다음 날 미제출=2배. 주간 표시 초기화는 원기록 삭제가 아니다. 모두 초기 요구이며 현재 판정은 이후 설계를 확인한다.

## 34. 원본 데이터 규칙

상점과 벌점은 별도 값이다. 상점-벌점을 벌점으로 부르지 않는다. 초기 자동 판정은 지정된 벌점값만 사용했다. 이후 원기록 보존+파생 NET 정책으로 발전했다.

## 35. 최종 요구

시작·메뉴·인증·DB·CRUD·계산·반성문·처분·Excel·검증·로딩/오류/빈 상태가 실제 동작해야 한다. 읽기 쉬운 TypeScript 구조와 개요·스택·환경변수·DB·이관·seed·개발·운영 배포 README를 제공한다. 장식용 가짜 버튼만 있는 화면은 요구 충족이 아니다.
