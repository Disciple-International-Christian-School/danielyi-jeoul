# DaS 주간 이력과 일별 입력 전환

**Language / 언어:** [English](HISTORY_AND_BACKFILL.md) | [한국어](HISTORY_AND_BACKFILL.ko.md)

> 최초 전환 기록이다. 이후 [수기 시험 초기화](OPERATIONS_2026-10-27.ko.md), [부서상점 재개](DEPARTMENT_MERITS.ko.md), [현재 규칙](DISCIPLINE_RULES.ko.md)이 운영 상태와 대상 기준을 대체한다. 원본 수치는 과거 근거로 보존한다.

## 운영 계약

원본 엑셀은 누적값이 아닌 독립된 주간 확정값이다. NET은 상점−벌점이며 구성 열은 그대로 보존하고 개별 사건을 재구성하지 않는다.

10/25까지 중고등 주간값은 공식 집계에서 이전 사건을 대체한다. 10/26부터 일별 사건과 적격 자동 상점을 같은 CORE UUID에 합산한다. 이전 사건은 point_records에 대체 이관과 연결해 보관하고 운영 뷰에서 제외한다. 승인된 DB 담당자가 불변 원본을 확인할 수 있다. 초등은 이관 범위 밖이므로 유지한다.

8/19–23 캠프(8/17 시작 주), 9/21–27 추석은 NO_SCHOOL이며 0점 관측이 아니다. 누락 학생은 누락으로 두고 비활성 신원의 이력도 보존한다. 알 수 없는 신원은 원본에 보관하며 새 활성 학생을 만들지 않는다. 진행 중이던 10/26–11/1 시트는 제외하고 DB와 중복이라고 추정하지 않는다. 이전 정산은 10/25 종료, 새 정산은 10/26 시작하며 학기 이력은 보존한다.

## 저장·수정·권한

history_settings는 학기·기준일·학년·활성 감사를, history_import_batches/history_source_rows는 원본·해시·좌표·구성값·NET·해결·이관자/시각을 보존한다. 큰 주석에서 사건을 만들지 않는다. history_aliases는 반별 명시 매핑이며 이름 접미사 일괄 삭제나 행 순서 연결은 금지한다.

weekly_balances는 학기/학생/주별 현재 1행과 과거 버전을 보존한다. 주간 대체는 기존 원본 신원을 모두 포함해야 하며 부분 업로드는 원자적으로 실패한다. 동일/0자리표시 중복은 같은 비0 확정값으로 통합한다. 서로 다른 비0 확정값은 실패시키고 중복 합산하지 않는다. 현재와 같은 업로드는 멱등적이고 과거 대체된 payload 재업로드는 거부한다. 변경본은 가산이 아닌 수정 버전이다.

get_discipline_history(student_id,start,end)는 정확한 주간 확정값·일별 기반 주간값·신원·원본 정밀도·검토·달력을 반환한다. 주간 원본의 incident_count는 null이다. 담당자는 학년 범위를 따르고 비관리자는 auth.uid()에 연결된 본인 Core ID만 조회한다. 익명 거부, 이관/상태/활성은 부장 전용이다. 새 테이블 6개에 RLS, 공개 RPC는 invoker, private 내부 함수는 명시 권한/소유 검사와 빈 search_path를 적용했다.

주간은 나눌 수 없다. 과거 구간의 하루 조회도 겹치는 주 전체 확정값이며 일점수라고 표시하지 않는다. 학기 합계는 가용 기록만 포함하고 누락·비운영 주를 0으로 채우지 않는다.

## 화면과 일별 운영

대시보드는 일/주/학기 이력과 부장 전용 이관 링크를 제공한다. 상세는 학기 주별 추이·정밀도·구성값·누락/비운영·비활성 신원을 지원한다. 수정 목록은 최근 100건이라고 표시하고 합계는 전체 RPC에서 얻는다.

XLSX 다중 시트·완료주 필터·원본 합계·중복/반 오류/큰 값 경고·미해결 신원·대체 검토·이관 이력·미해결 원행을 제공한다. 수기 사유는 필수·DB 80자 제한이며 preset 변경 시 점수를 초기화하고 연속입력은 사유를 유지한다. 요청 UUID로 재시도 중복을 막고 최근 취소·기준일/미래일 제한을 제공했다. 과거일 제한은 이후 초기화 결정으로 완화됐다.

운영 벌점−상점은 순벌점, 원본 호환 합계는 최종값/학기누계=상점−벌점으로 표시했다. 반성문 연장은 발생 다음날 17시 KST, 토/일 발생은 월요일 17시이며 금요일은 이 문언상 토요일이다. 기본 마감은 유지, 제출완료는 연장 불가, 구 RPC도 같은 규칙이다. 출력 안내는 즉시 미리보기와 페이지 안 임시 저장이며 공통 공지가 아니다. 부서 생성은 최초 조회/새 모드를 구분하고 자동 상점은 원본키·동시 재시도·이관된 과거 중고등 주 제외를 지킨다.

## 규칙 시트 대조

새 정책·점수를 만들지 않았다. 등교지각/등교 지각, 욕설·비속어/욕설의 표기 차이, 세상노래 가창/연주 각 7과 기존 통합 7, 교실 미소등/미소등 2는 검토로 남겼다. 원본 빈 점수는 0이나 기존값 삭제 요청이 아니다. 등교 지각·잔반의 기존 2점은 유지했다.

원본 전용 고정값은 교실 미정리·냉난방 문단속·슬리퍼 등교·복도통행·선풍기 가동·체육복 미착용 각 2, 성경책 미지참 5다. 현재 preset이 없어 수기입력으로 처리하며 카탈로그 동기화는 정책 판단이다. 교외 실내화·교내 실외화·식후 테이블 미정리·교내 취식·복도 양치는 원본 점수가 비어 있어 임의 고정값을 만들지 않았다. 앱 전용 암송 미완료·일기 미제출·수업태도 불량·선생님 재량은 유지하며 재량 1–5 검사도 유지했다.

## 검증과 남은 범위

타입·빌드·날짜 경계·파서 중복/부호/날짜/셀 검사를 통과했다. DB 롤백은 원본/연결 합계, 반성문 미생성, 초등/현재 사건 보존, 반복/부분 업로드, 수기 멱등성·기준일·자동 재시도, 담당자 권한·본인/타인·익명 거부, KST 연장을 확인했다. 원자 이관 후 운영을 재조회했다.

새 보안 경고는 없었고 새 이력 FK 인덱스 지적은 후속 이관으로 해결했다. 기존 타 앱 경고는 별도이며 [공식 검사 참고](https://supabase.com/docs/guides/database/database-linter)를 따른다. 브라우저는 운영 로그인까지 도달했지만 관리자 세션이 없어 실계정 화면 인수를 완료했다고 주장하지 않는다.

SP/학생 현황판 연결, 미해결 과거 신원, 100점 원본 검토, 선택 카탈로그 통일, 개인계정 대상, 학생 Auth/PIN은 후속 과제다. 공통 읽기 API는 준비했지만 다른 앱은 이 작업에서 변경하지 않았다.
